# Worldmap Blips (WordPress Plugin)

Плагин добавляет интерактивную карту (Leaflet) с «метками-точками» (blips), попапами и слайдером контента для каждого объекта.

## 1) Установка и базовое подключение

### Установка
1. Скопируйте папку плагина `worldmap-blips` в каталог `wp-content/plugins/`.
2. В админке WordPress откройте **Плагины → Установленные плагины**.
3. Активируйте **Worldmap Blips**.

### Активация
После активации:
- регистрируются типы данных плагина (если предусмотрены реализацией);
- подключаются фронтенд/админ-ассеты;
- становятся доступны shortcode и блок Gutenberg.

> Если плагин поставляется архивом: **Плагины → Добавить новый → Загрузить плагин**.

### Shortcode
Используйте shortcode в контенте страницы/записи:

```text
[worldmap_blips]
```

Если реализация поддерживает атрибуты, можно указывать их напрямую, например:

```text
[worldmap_blips zoom="2" height="600"]
```

### Gutenberg block
1. Откройте страницу в редакторе Gutenberg.
2. Добавьте блок **Worldmap Blips**.
3. Настройте параметры блока (масштаб, центр, высота, фильтры категорий/меток — если доступны).

### PHP-вставка в шаблон
Для вывода карты в теме (template file):

```php
<?php echo do_shortcode('[worldmap_blips]'); ?>
```

Или (если плагин предоставляет функцию рендера) использовать её в шаблоне темы.

## 2) Настройки и управление метками

### Где настраивать
Рекомендуемый путь в админке (может отличаться в зависимости от реализации):
- **Worldmap Blips → Settings**
- или **Settings → Worldmap Blips**

### Типовые настройки
- **Карта:** дефолтный zoom, центр, min/max zoom, стиль контролов.
- **Визуал:** цветовая схема (black/gold/white), размеры/тип маркеров, поведение попапа.
- **Контент попапа:** заголовок, описание, медиа, слайдер.
- **Мобильное поведение:** стартовый zoom, drag/touch, адаптивные отступы.
- **Производительность:** lazy load слоёв/изображений, кеширование данных меток.

### Управление метками (blips)
Обычно каждая метка содержит:
- `title` — название;
- `latitude`, `longitude` — координаты;
- `category/tag` — группировка/фильтрация;
- `content` — HTML/текст попапа;
- `media` — изображения для слайдера.

Типовой процесс:
1. Создать метку в админке плагина.
2. Заполнить координаты и контент.
3. Назначить категорию/теги.
4. Опубликовать и проверить отображение на карте.

## 3) Требования и зависимости

### Системные требования
- **PHP:** `8.0+` (рекомендуется `8.1+`).
- **WordPress:** поддерживаемые версии — `6.0+` (рекомендуется актуальная стабильная ветка).
- **MySQL/MariaDB:** в соответствии с минимальными требованиями WordPress.

### JS/CSS-зависимости
Плагин использует:
- **Leaflet** — рендер карты и слоёв;
- **Swiper** — слайдер в карточке/попапе;
- **Micromodal** — модальные окна для расширенного контента.

> Рекомендуется подключать версии библиотек, совместимые с текущей версией WordPress и без конфликтов с темой/другими плагинами.

## 4) Импорт, экспорт и миграция данных

### Экспорт
Варианты экспорта (в зависимости от реализации):
- через встроенный экспорт меток в JSON/CSV;
- через стандартный WordPress Export (`Tools → Export`) для соответствующего post type;
- через WP-CLI/кастомные команды.

### Импорт
- Импорт из JSON/CSV через интерфейс плагина.
- Или импорт post type стандартными инструментами WordPress.

### Рекомендуемый сценарий миграции (dev/stage/prod)
1. Экспортировать метки и связанные таксономии на источнике.
2. Перенести медиафайлы (`uploads`) при наличии изображений в попапах.
3. Импортировать данные на целевой сайт.
4. Проверить соответствие ID/slug категорий и корректность координат.
5. Прогнать smoke-тест: рендер карты, попапы, фильтры, мобильный UI.

### Важные нюансы
- Следите за кодировкой (`UTF-8`) при CSV.
- При миграции между доменами обновляйте URL медиа.
- При больших объёмах данных используйте пакетный импорт.

## 5) Безопасность

При разработке/аудите убедитесь, что реализованы:

- **Nonce-проверки** для всех админ-форм и AJAX/REST-операций, изменяющих данные.
- **Проверка прав (permissions/capabilities)** перед CRUD-операциями (например, `manage_options`, `edit_posts` или кастомные capability).
- **Sanitization/Validation** входных данных:
  - `sanitize_text_field`, `sanitize_key`, `absint`, `floatval` и т.д.;
  - валидация диапазонов координат и zoom.
- **Escaping при выводе**:
  - `esc_html`, `esc_attr`, `esc_url`, `wp_kses_post`.
- **Защита REST/AJAX-эндпоинтов** от неавторизованных запросов.

## 6) Производительность

Рекомендации для production:

- **Lazy load** изображений/слайдов и тяжёлых UI-компонентов.
- **Кеширование**:
  - кэш подготовленного набора меток (transients/object cache);
  - HTTP-кеш для статических ассетов.
- **Минимизация запросов**:
  - батч-загрузка данных меток;
  - ограничение полей в ответах REST/AJAX.
- **Оптимизация фронтенда**:
  - минификация JS/CSS;
  - отложенная инициализация Swiper/Micromodal;
  - отключение лишних обработчиков на mobile.

## 7) Acceptance checklist (по ТЗ)

Перед релизом проверьте:

### Функциональность карты
- [ ] Корректный **zoom** (дефолт, min/max, wheel/touch).
- [ ] Корректное центрирование и позиционирование всех меток.
- [ ] Работают popups у всех маркеров.

### Popups и контент
- [ ] Popup открывается/закрывается без артефактов.
- [ ] Swiper в popup корректно листает слайды.
- [ ] Micromodal не конфликтует с popup и focus trap.

### Mobile/Responsive
- [ ] UI корректен на мобильных ширинах.
- [ ] Touch-жесты карты работают предсказуемо.
- [ ] Нет «залипаний» скролла и перекрытия элементов.

### Дизайн
- [ ] Соответствие палитре **black / gold / white**.
- [ ] Контраст текста достаточен (читабельность).
- [ ] Стиль маркеров/попапов соответствует макетам.

### Качество и стабильность
- [ ] Отсутствуют PHP warnings/notices/fatal errors.
- [ ] Отсутствуют JS errors в консоли браузера.
- [ ] Нет конфликтов с активной темой и популярными плагинами кэша/SEO.
- [ ] Проверены сценарии импорта/экспорта и повторной миграции.

## 8) Быстрый smoke-test после деплоя

1. Открыть страницу с `[worldmap_blips]`.
2. Проверить рендер карты и меток.
3. Открыть несколько popup, проверить слайдер.
4. Проверить mobile viewport.
5. Проверить консоль браузера и debug.log.
